# TinyML: TinyTalk на ESP32-S3 N16R8

Локальный текстовый чат с TinyTalk 2: ввод через USB, ответ в USB-консоли
и на SSD1306. Веса и токенизатор уже включены в проект. Для генерации
не нужны Wi-Fi, API или отдельный сервер.

Это маленькая экспериментальная англоязычная модель с коротким контекстом,
а не универсальный помощник. Она может выдумывать ответы. Распознавание речи,
микрофон и озвучивание пока не подключены.

## Поговорить на компьютере

Для экспериментов с английским персонажем есть отдельный
[локальный учитель на Mac](docs/local-teacher.md). Он нужен для подготовки
обучающих диалогов; это более крупная модель, чем текущая модель на ESP32.
Программа обучения маленького ученика и его отдельный чат описаны в
[эксперименте со stories15M](docs/dragon-training.md).

Нужны macOS или Linux, Bash и C++17-компилятор (`c++`, либо переменная `CXX`).
ESP-IDF для этого не нужен:

```sh
bash tools/chat.sh
```

Скрипт собирает программу в `build/host/` и запускает ту же консоль с теми же
весами, что используются на ESP32. После `You>` введите, например, `Hi!`.
Для выхода нажмите Ctrl+C. Скорость на компьютере не отражает скорость платы:
здесь используются обычные CPU-потоки и переносимые вычисления вместо Xtensa SIMD.

Команды:

| Команда | Действие |
| --- | --- |
| `/new` | Очистить историю |
| `/temp 0` | Выбирать самый вероятный токен, удобно для повторяемых проверок |
| `/temp 0.8` | Вернуть начальную температуру (допустимо 0…2) |
| `/stats` | Показать модель, историю и на ESP32 свободную память |
| `/help` | Справка |

Ввод ограничен 256 байтами и 64 токенами вместе с оформлением запроса;
слишком длинный запрос отклоняется. Ответ — до 48 токенов. История содержит
до четырёх пар реплик; в следующий запрос попадают только помещающиеся
последние пары. KV-кэш — 72 позиции со сдвигом при заполнении.

## Сборка и прошивка

Целевая плата: ESP32-S3 N16R8, 16 MB flash, 8 MB Octal PSRAM.
Используется ESP-IDF 6.1.x. После активации установленного ESP-IDF:

```sh
idf.py set-target esp32s3
idf.py build
idf.py -p /dev/ttyACM0 flash monitor
```

`set-target` пересоздаёт конфигурацию и сохраняет прежнюю в `sdkconfig.old`.
Если в ней были собственные настройки, сохраните их заранее и перенесите
нужные значения. `sdkconfig.defaults` применяется при создании конфигурации;
он не заменяет значения уже существующего `sdkconfig`.

Настроены 240 MHz, flash QIO 80 MHz, Octal PSRAM 80 MHz, консоль UART0
115200 через USB–UART-переходник платы. Таблица разделов содержит один большой factory-раздел без OTA.
Это меняет разметку исходного проекта. Модель лежит в flash, рабочие буферы
движка используют внутреннюю SRAM. При запуске проверяется наличие 8 MB PSRAM.

Дождитесь `[READY]` и приглашения `You>`. Для выхода из `idf.py monitor`
используйте Ctrl+]. Во время генерации ввод обрабатывается после завершения
ответа; отдельного прерывания генерации пока нет.

### Если монитор показывает только `ESP-ROM` и `entry ...`

На этой плате `/dev/ttyACM0` соответствует переходнику QinHeng CH343
(`1a86:55d3`), а не встроенному USB Serial/JTAG ESP32-S3. В первой версии
проекта консоль была ошибочно настроена на встроенный USB: сообщения ROM
были видны через UART, а вывод загрузчика ESP-IDF и программы уходил на другой
интерфейс. Теперь по умолчанию выбран UART0.

Если `sdkconfig` уже создан, одного `git pull` недостаточно. Запустите
`idf.py menuconfig`, откройте **Component config → ESP-STDIO →
Channel for console output** и выберите **Default: UART0**. Скорость — 115200.
Либо замените соответствующие строки в `sdkconfig` (без дубликатов):

```ini
CONFIG_ESP_CONSOLE_UART_DEFAULT=y
# CONFIG_ESP_CONSOLE_USB_SERIAL_JTAG is not set
CONFIG_ESP_CONSOLE_UART_BAUDRATE=115200
```

Закройте старый монитор через Ctrl+] и выполните:

```sh
idf.py -p /dev/ttyACM0 flash monitor
```

При использовании другого разъёма, подключённого напрямую к USB ESP32-S3,
выбирайте USB Serial/JTAG вместо UART0. Само имя `ttyACM` не определяет тип
подключения. Его можно проверить через
`udevadm info --query=property --name=/dev/ttyACM0`.

Первой сборке нужен интернет для драйвера `chill-sam/ssd1306` версии 1.1.2.
Каталог `managed_components` создаёт Component Manager; прежняя неполная
ссылка на git submodule удалена. `dependencies.lock` фиксирует зависимости.

## Экран

SSD1306 128×64, I2C: SDA GPIO13, SCL GPIO14, адрес `0x3C`.
Верхняя строка показывает состояние, семь нижних — ответ с переносом и
прокруткой. Настройки находятся в `idf.py menuconfig` → `TinyML`.
Экран можно отключить; если он не найден, чат продолжает работать через USB.
Оригинальный `main/test.c` сохранён как пример диагностики и не входит в сборку.

## Проверка на компьютере

```sh
python3 tools/check_host.py
```

Проверяются реальные веса, воспроизводимость ответа после сброса истории,
ограничения ввода и прокрутка текста. Эти проверки не заменяют запуск на плате:
они не проверяют Xtensa SIMD, USB, I2C и доступную SRAM.

Локально проверено 2026-10-17: эти проверки прошли на macOS arm64;
прошивка собрана ESP-IDF v6.1 для ESP32-S3 с консолью UART0 115200
в загрузчике и приложении. Размер образа — 6 195 760 байт
(5,91 МиБ), раздел приложения — 16 711 680 байт. Проверено включение SIMD-ядра
и выравнивание встроенных весов в ELF. Запуск на физической плате пока не проверен.
