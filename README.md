# TinyML: PLE TinyStories на ESP32-S3 N16R8

Для ИИ-агентов: [цель проекта, текущее состояние и правила продолжения](AGENTS.md).

Модель **PLE TinyStories 28,9M из slvDev/esp32-ai** работает на самой ESP32.
Ввод и вывод идут через **native USB Serial/JTAG ESP32**, обнаруженный в логе
пользователя как `303a:1001` (`/dev/ttyACM0`, драйвер `cdc_acm`). Текст также
отображается на SSD1306. Веса и токенизатор включены в репозиторий; Wi-Fi и сервер
не нужны. Для отдельного USB–UART-моста доступна настройка UART0.

Эта модель **продолжает английские истории**, а не обучена отвечать на вопросы
или вести разговор от лица Ember. Например, введите `Once upon a time` или
`There was a little dragon named Ember.`. Каждый ввод начинает новую историю.
Модель может повторяться и выдумывать. Микрофон и озвучивание пока не подключены.
Перенос и проверка оптимизаций описаны в [отчёте](docs/esp32ai-port.md).

## Поговорить на компьютере

Отдельно доступны **Stentor 30M Q4, Stories42M Q4 и VaghLM 42,6M FP32**:
`bash tools/small_models.sh` открывает меню выбора.
[Установка, команды и ограничения моделей](docs/small-models-playground.md).

Для экспериментов с английским персонажем есть отдельный
[локальный учитель на Mac](docs/local-teacher.md). Он нужен для подготовки
обучающих диалогов; это более крупная модель, чем текущая модель на ESP32.
Программа обучения маленького ученика и его отдельный чат описаны в
[эксперименте со stories15M](docs/dragon-training.md).
Проверки других моделей с персонажем через системный промпт и новые исследования
собраны в [сравнении разговорных кандидатов](docs/dialogue-candidates.md).
Возобновляемая генерация черновых диалогов Qwen описана в
[подготовке корпуса](docs/dragon-corpus.md); оценка объёма данных и подходящих
архитектур — в [исследовании масштаба обучения](docs/research/dragon-training-scale.md).
Обучение MiniMind с переменной ролью, проверка забывания и результаты двух
вариантов описаны в [отчёте об обучении диалогу](docs/dialogue-training-v1.md).

Нужны macOS или Linux, Bash и C++17-компилятор (`c++`, либо переменная `CXX`).
ESP-IDF для этого не нужен:

```sh
bash tools/chat.sh
```

Скрипт собирает программу в `build/host/` и запускает ту же консоль с теми же
весами, что используются на ESP32. После `You>` введите, например, `Once upon a time`.
Для выхода нажмите Ctrl+C. Скорость на компьютере не отражает скорость платы:
здесь используется переносимый код на одном ядре CPU; аппаратная проверка нужна отдельно.

Команды:

| Команда | Действие |
| --- | --- |
| `/new` | Очистить экран; каждый ввод и так начинает новую историю |
| `/temp 0` | Выбирать самый вероятный токен, удобно для повторяемых проверок |
| `/temp 0.8` | Включить случайный выбор токенов (допустимо 0…2; начальное значение 0) |
| `/stats` | Модель, размещение памяти, два ядра и настройки ESP32 |
| `/memory` | Память модели, heap PSRAM/SRAM, крупнейшие свободные блоки и flash-разделы |
| `/bench` | 200 токенов, greedy, USB-вывод и профиль времени, без обновлений OLED |
| `/bench oled` | Тот же замер с обновлениями OLED |
| `/help` | Справка |

Ввод ограничен 256 байтами ASCII и 128 токенами. Продолжение — до 128 токенов
или EOS. Контекст/KV-кэш — 256 позиций; история диалога между вводами не хранится.
`/bench` использует фиксированные четыре токена `Once upon a time` и ровно 200
шагов, как исходный пример. Подробнее о сравнимости замеров — [в отчёте](docs/esp32ai-port.md).

## Сборка и прошивка

Для отчёта по памяти собранных файлов без платы: `python3 tools/memory_report.py`.
Живые показания после загрузки модели: `/memory` в USB-консоли. Возможности
расширения и пределы для 300M описаны в [отчёте памяти](docs/memory-report.md).
Отдельный компьютерный эксперимент GPT-2 не меняет модель прошивки:
[запуск без истории и проверка качества](docs/evaluation/gpt2-small/README.md).

Целевая плата: ESP32-S3 N16R8, 16 MB flash, 8 MB Octal PSRAM.
Используется ESP-IDF 6.1.x. После активации установленного ESP-IDF:

```sh
python3 tools/configure_console.py build/esp32ai-sdkconfig --interface usb
idf.py -B build/esp32ai -D SDKCONFIG="$PWD/build/esp32ai-sdkconfig" build
idf.py -B build/esp32ai -p /dev/ttyACM0 flash monitor
```

`configure_console.py` создаёт конфигурацию из defaults или исправляет в существующей
выбор консоли, скорость и необходимый для USB ввод/вывод VFS. Перед изменением сохраняет копию `.before-usb-*` (либо `.before-uart0-*`).
Команды используют отдельную конфигурацию, оставляя
существующий корневой `sdkconfig` на месте. Цель esp32s3 задана в defaults.
Если `build/esp32ai-sdkconfig` уже существует, первая команда исправит выбранный
интерфейс: defaults самостоятельно существующие значения не перезаписывает.
Порт замените на свой; на Mac обычно `/dev/cu.usbserial-*` или `/dev/cu.usbmodem*`.

Настроены 240 MHz, flash QIO 80 MHz, Octal PSRAM 80 MHz, основная консоль
USB Serial/JTAG для ввода и вывода. В приложении включён стандартный USB-драйвер
ESP-IDF с прерываниями: короткое приглашение `You>` не ждёт заполнения USB-буфера
или перевода строки для отправки. Новая разметка: приложение 1 МиБ с
`0x10000`, модель в отдельном разделе с `0x110000` размером `0xEF0000`.
**При первом переходе выполняйте `flash`, а не `app-flash`: нужны и новая таблица
разделов, и модель.** `flash` автоматически включает проверенные веса.
OTA-разделов нет; новая разметка заменяет прежний большой factory-раздел.

Большая PLE-таблица остаётся во flash; часто читаемые веса int8, logits и KV —
в PSRAM; рабочие буферы и нормы — во внутренней SRAM. Проверяется наличие 8 МиБ
PSRAM и совпадение отпечатка модели. Если весов нет или они повреждены,
программа остановится с `[FATAL]`, а не начнёт генерировать с неверной моделью.

Дождитесь `[READY]` и приглашения `You>`. Для выхода из `idf.py monitor`
используйте Ctrl+]. Во время генерации ввод обрабатывается после завершения
ответа; отдельного прерывания генерации пока нет.

### Выбор между native USB и USB–UART

Имя `ttyACM0` не определяет интерфейс. Последний лог пользователя подтвердил
**Espressif `303a:1001`** — прямое USB-подключение к ESP32. Ранее в проекте
использовался CH343; переносить его настройку на текущее подключение нельзя.

| Подключённое устройство | Команда настройки |
| --- | --- |
| `303a:1001`, Espressif USB JTAG/serial debug unit | `python3 tools/configure_console.py build/esp32ai-sdkconfig --interface usb` |
| USB–UART-мост, например QinHeng CH343 `1a86:55d3` | `python3 tools/configure_console.py build/esp32ai-sdkconfig --interface uart0` |

После настройки выполните build/flash/monitor с тем же `-B build/esp32ai`, как
выше. В режиме `usb` и ввод, и вывод идут на USB Serial/JTAG. В режиме `uart0`
команды принимает UART0 115200, а native USB остаётся дополнительным выходом.
**Secondary USB не принимает команды** — одного зеркалирования недостаточно.
`tools/configure_uart0.py` сохранён как прежний способ выбрать режим моста;
для текущего `303a:1001` его запускать не нужно.

После старта `/stats` в режиме native USB должен показывать:

```text
[console] input=USB_SERIAL_JTAG output=USB_SERIAL_JTAG
```

Если видны только ROM-строки, сначала проверьте выбранный интерфейс и выполните
полный `flash` в нужном build-каталоге. Сведения об устройстве можно получить
через `lsusb` и `udevadm info --query=property --name=/dev/ttyACM0`.

Первой сборке нужен интернет для драйвера `chill-sam/ssd1306` версии 1.1.2.
Каталог `managed_components` создаёт Component Manager; прежняя неполная
ссылка на git submodule удалена. `dependencies.lock` фиксирует зависимости.

### Если монитор не открывает порт: `[Errno 71] Protocol error`

Это ошибка открытия/настройки serial-порта на Linux, а не сообщение модели.
Номер `/dev/ttyACM0` в списке ещё не означает, что порт можно успешно открыть.
Настройка консоли меняет маршрутизацию ввода/вывода прошивки; ошибка открытия USB требует
проверки на компьютере, к которому физически подключена плата.

Закройте мониторы и другие программы, использующие порт. В активированной
среде ESP-IDF выполните:

```sh
python tools/diagnose_usb.py /dev/ttyACM0
```

Скрипт сохранит лог в `build/usb-diagnostics/`: USB VID/PID, сведения об
использующем порт процессе, попытку открытия через pyserial и последние строки
журнала ядра. Открытие может перезапустить плату через DTR/RTS; скрипт ничего
не прошивает, не меняет драйверы и не останавливает службы. Если чтение
журнала ядра запрещено, отдельно выполните `sudo dmesg --ctime | tail -80`.
Пришлите лог для определения причины. Автоматическое удаление драйверов или
отключение системных служб без подтверждённой причины не требуется.

В первом присланном 2026-10-18 логе монитор использовал каталог `build`, а новая
прошивка собирается в `build/esp32ai`. Пользуйтесь одним и тем же `-B` при
сборке, прошивке и monitor; это исключает использование прежней конфигурации
и старого ELF, но само по себе не доказывает исправление USB Protocol error.

## Экран

SSD1306 128×64, I2C: SDA GPIO13, SCL GPIO14, адрес `0x3C`.
Верхняя строка показывает состояние, семь нижних — ответ с переносом и
прокруткой. Передача кадра по I2C 400 кГц выполняется не чаще раза в 0,5 с
и в конце ответа, чтобы не тормозить каждый токен. Настройки находятся в `idf.py -B build/esp32ai menuconfig` → `TinyML`.
Экран можно отключить; если он не найден, чат продолжает работать через USB.
Оригинальный `main/test.c` сохранён как пример диагностики и не входит в сборку.

## Проверка на компьютере

```sh
python3 tools/check_host.py
```

Проверяются реальные веса, воспроизводимость продолжения, сброс контекста,
ограничения ввода, 200-токенный benchmark, повреждённая модель, upstream
int8 staging и прокрутка текста. Отдельная проверка BPE против Hugging Face
требует пакет `tokenizers` (проверено с 0.23.3):

```sh
python3 tools/check_esp32ai_tokenizer.py
```

Локально проверено **2026-10-18**: host-проверки прошли на macOS arm64;
1106 входов ASCII ранее совпали с Hugging Face. Регрессия неверного выбора
primary для `303a:1001` сначала воспроизведена тестом, затем исправлена;
миграции USB/UART0 и сохранение пользовательских настроек проверяются командами:

```sh
python3 tools/test_configure_console.py
python3 tools/test_configure_uart0.py
python3 tools/check_usb_build.py build/esp32ai
```

Прошивка собрана ESP-IDF v6.1 с USB Serial/JTAG как primary в приложении и
bootloader, 16 МиБ flash, Octal PSRAM 80 MHz, CPU 240 MHz.
[Данные новой сборки](docs/evaluation/esp32ai/native-usb-build-receipt.json).
Пользователь подтвердил открытие USB-порта в Linux; ввод команд и запуск модели
после смены primary пока не подтверждены на устройстве.
**9,88 токена/с и 94,9 мс/токен — ориентиры автора, на этой плате ещё не измерены.**
