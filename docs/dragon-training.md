# Пробное дообучение stories15M

Ученик — `karpathy/tinyllamas` stories15M, 15 191 712 параметров.
Учитель — локальная Qwen3.5-9B. Это supervised fine-tuning на текстах учителя
(sequence-level distillation), без переноса его весов или сопоставления logits.
Весь эксперимент выполняется на компьютере; текущая прошивка пока использует TinyTalk 2.

Для первого опыта персонаж фиксирован: Ember, маленький дружелюбный дракон,
тёплая пещера, яблоки и блестящие камешки. Роль обучается в весах. Вход ученика
содержит только `User: ...\nDragon:` и недавние пары реплик. Между парами
стоит EOS; каждое новое окно начинается с BOS. Максимум — 256 токенов,
при проверке оставляется 48 токенов на ответ. Старые пары удаляются целиком.

## Воспроизведение

Нужны Python, PyTorch, NumPy и SentencePiece. На используемом Mac окружение
находится в `~/.cache/tinyml-eval-venv`, код/токенизатор — в
`~/.cache/tinyml-llama2c`. Закреплённый код llama2.c:
`350e04fe35433e6d2941dce5a1f53308f87058eb`.
Исходные веса и лицензии описаны в [исследовании](dragon-model-research.md).

Сначала запустите [локального учителя](local-teacher.md). Затем из корня проекта:

```sh
python3 tools/dragon_data.py
python3 tools/prepare_dragon_pilot.py

~/.cache/tinyml-eval-venv/bin/python tools/dragon_student.py eval \
  --upstream ~/.cache/tinyml-llama2c \
  --checkpoint ~/.cache/tinyml-llama2c/stories15M.pt \
  --device cpu --output build/dragon/student-before.json

~/.cache/tinyml-eval-venv/bin/python tools/dragon_student.py train \
  --upstream ~/.cache/tinyml-llama2c \
  --checkpoint ~/.cache/tinyml-llama2c/stories15M.pt \
  --device mps --data build/dragon/pilot-data \
  --output build/dragon/pilot-training --epochs 8

~/.cache/tinyml-eval-venv/bin/python tools/dragon_student.py eval \
  --upstream ~/.cache/tinyml-llama2c \
  --checkpoint build/dragon/pilot-training/best.pt \
  --device cpu --output build/dragon/student-after.json
```

На компьютере без Metal используйте `--device cpu`. Генератор данных сохраняет
готовые разговоры по одному и продолжает с пропущенного места. Изменив модель,
сценарии или параметры генерации, укажите новый `--output`; смешивать такие
запуски в одном наборе нельзя. Повторная генерация может дать другие тексты
даже с тем же seed; для точного повторения обучения нужны сохранённые JSONL.

`prepare_dragon_pilot.py` фиксирует отдельную копию после фильтрации: удаляет
неоднозначные задания и замеченные при чтении ошибки учителя. Автоматически
отклоняются обрезанные/пустые/слишком длинные ответы, неподходящие символы,
отсутствие ожидаемых фактов. Наличие нужного слова само по себе не означает
правильный ответ. Фильтр строгий: может отбросить корректный синоним.

Учимся предсказывать только ответы assistant и EOS. История и текущий вопрос
остаются во входе, но исключены из loss. AdamW, gradient clipping 1.0,
начальный LR 0.0002 с cosine decay до 10%, batch 8, seed 42. Выбирается
checkpoint с минимальным loss на validation, а не по контрольным вопросам.

## Проверки и границы выводов

```sh
DRAGON_TOKENIZER=~/.cache/tinyml-llama2c/tokenizer.model \
  ~/.cache/tinyml-eval-venv/bin/python tools/test_dragon_student.py
```

Проверены сдвиг целевых токенов, маскирование вопроса/истории/паддинга,
обучение EOS и удаление целых старых ходов при переполнении контекста.

Train и validation разделены по разговорам, именам и формулировкам; общие
темы пересекаются. Отдельные десять сценариев `dragon_teacher.CASES` не входят
в обучающие данные. Оценка ведётся с ответами самого ученика в истории,
а не с идеальными репликами учителя. Greedy-декодирование одинаково до и после.

Это небольшой эксперимент, не проверка общего интеллекта или устойчивости
на произвольных разговорах. Из-за повторяющихся шаблонов возможны заучивание
ответов, потеря разнообразия и ухудшение других способностей. Результаты FP32
не доказывают качество Q4 и скорость ESP32; для них нужны отдельные проверки.

## Поговорить с учеником

После обучения:

```sh
~/.cache/tinyml-eval-venv/bin/python tools/dragon_student.py chat \
  --upstream ~/.cache/tinyml-llama2c \
  --checkpoint build/dragon/pilot-training/best.pt
```

Это stories15M, а не Qwen. `/new` очищает историю, `/quit` завершает чат.
Память ограничена текущим окном диалога и не сохраняется между запусками.

## Выполненные опыты и результат

17 октября 2026 года выполнены два набора SFT и контроль на другой базе.
Качество свободного разговора пока недостаточное. Получились короткие ответы
в образе дракона, но обобщение новых формулировок и привязка имён остаются слабыми.

1. Первый набор: 171 разговор / 257 ответов для обучения, 12 / 16 для
   validation. stories15M, 8 эпох; лучшая — вторая, validation loss
   4,033 → 1,936. На прежних десяти сценариях EOS улучшился с 0/15 до 15/15,
   но проверка ключевых слов осталась 3/8. Эти сценарии затем использовались
   как development-набор при изменении дизайна данных.
2. Второй набор: 378 разговоров / 627 ответов, validation 24 / 32.
   Учитель отвечает одной короткой фразой; больше имён, вариантов представления,
   исправлений и вопросов. Полное обучение stories15M: лучший loss 1,569
   на первой эпохе. С замороженными embedding: 2,135 на второй.
   Выбор полного обучения зафиксирован по validation до просмотра нового теста.
3. Контрольная база TinyTalk 2 (GPT-Neo): тот же второй набор, 6 эпох,
   LR 0,00005, лучший loss 0,975 на второй эпохе. В отличие от stories15M,
   эта база уже обучалась чатам. Она говорит естественнее, но полноценной
   надёжности также не достигла. Это отдельный опыт; перенос в прошивку не выполнен.

Новый набор [`heldout-v2.json`](../tests/dragon/heldout-v2.json) создан до
окончания подготовки второго набора. Имена Elena, Hugo, Nora, Iris отсутствуют
в его обучающих текстах. 20 сценариев / 29 ответов; 13 сценариев имеют
автоматическую проверку слов. После просмотра результата stories15M этот
набор использован и для исследовательского сравнения TinyTalk; считать его
в дальнейшем нетронутым финальным тестом уже нельзя.

| Модель | Ожидаемые слова присутствуют | Естественное завершение EOS |
|---|---:|---:|
| stories15M исходная | 4/13 | 0/29 |
| stories15M после второго SFT | 2/13 | 29/29 |
| Та же, имитация Q4 весов | 3/13 | 29/29 |
| TinyTalk исходная FP32 | 1/13 | 29/29 |
| TinyTalk после второго SFT | 3/13 | 29/29 |

Проверка слов **не является точностью ответов**: ответ с нужным именем может
перепутать роли или содержать отрицание. Q4 здесь также не означает улучшения
качества: несколько изменённых токенов случайно меняют этот грубый показатель.
При чтении видно, что stories15M заменяет Elena на Ella, TinyTalk — Elena
на Lena, а исправление на Iris превращает в Amanda. Обе модели теряют смысл
сложнее сформулированных вопросов. Более длительное обучение этих же примеров
увеличивает переобучение.

Проверка реализации: CPU validation loss выбранной stories15M — 1,569401,
MPS — 1,569422. Сдвиг labels, маски и EOS проверены тестами; имитация Q4
совпала побитно после деквантования с upstream-конвертером на 512 блоках.
Имитация меняет только матрицы весов; арифметика FP32, кэш и активации не
соответствуют всем деталям ESP-движка. Результаты и настройки:
[`docs/evaluation/dragon-pilot`](evaluation/dragon-pilot).

## Повторить второй опыт

Готовые отфильтрованные данные сохранены в
[`training/dragon/pilot-v2`](../training/dragon/pilot-v2).
Они позволяют повторить обучение без повторной генерации учителем:

```sh
~/.cache/tinyml-eval-venv/bin/python tools/dragon_student.py train \
  --upstream ~/.cache/tinyml-llama2c \
  --checkpoint ~/.cache/tinyml-llama2c/stories15M.pt \
  --device mps --data training/dragon/pilot-v2 \
  --output build/dragon/pilot-training-v2 --epochs 8
```

Для варианта с фиксированной таблицей слов добавьте `--freeze-embeddings`
и используйте другой `--output`. Для генерации нового набора:

```sh
python3 tools/dragon_data.py --variant concise --output build/dragon/data-v2
python3 tools/prepare_dragon_pilot.py --input build/dragon/data-v2 \
  --output build/dragon/pilot-data-v2 --review training/dragon/concise-review.json
```

Ручной review относится к сохранённому прогону. При повторной генерации
прочитайте новые ответы: список исключений не заменяет проверку нового набора.
Дополнительно фильтр отбрасывает ответы, где учитель присваивает себе имя пользователя.

Контроль TinyTalk использует локальные исходные веса из `esp32-tinytalk`
(commit указан в основном README). Он сохраняет исходный tokenizer и метку `Bot:`:

Здесь используется полный словарь 50 257, а текущий ESP-экспорт имеет 12 929
токенов. Перед внедрением нужно согласовать словарь обучения с целевым
токенизатором и отдельно проверить сохранение имени Ember после сокращения
словаря. Текущий FP32 checkpoint нельзя просто заменить в прошивке.

```sh
~/.cache/tinyml-eval-venv/bin/python tools/dragon_student.py train \
  --architecture gpt-neo --upstream ~/esp32-tinytalk/data/chat_model_8m \
  --checkpoint ~/esp32-tinytalk/data/chat_model_8m/model.safetensors \
  --device mps --data training/dragon/pilot-v2 \
  --output build/dragon/neo-training --epochs 6 --lr 0.00005
```

В текущем рабочем Mac checkpoints уже сохранены. Короткие команды для чата:

```sh
bash tools/dragon_chat.sh stories
bash tools/dragon_chat.sh tinytalk
```

Первый вариант использует локальную ссылку `build/dragon/current.pt` на
`pilot-training-v2/best.pt`. На свежем клоне её нужно создать после обучения:
`ln -s pilot-training-v2/best.pt build/dragon/current.pt`.
Сами большие checkpoints находятся в `build/`, в Git они не добавлены.
Скрипты, данные и протоколы сохранены в репозитории. Для своих путей можно
задать `DRAGON_PYTHON`, `DRAGON_UPSTREAM`, `DRAGON_CHECKPOINT`.

Следующая исследовательская проверка — более разнообразное базовое обучение
диалогам и отдельные примеры различения говорящих; возможное смешивание
с исходными текстами нужно проверять отдельным опытом. Сотни реплик персонажа
оказались достаточны для стиля, но недостаточны для надёжного диалога.

Обзоры первичных публикаций: [дистилляция и данные](research/dragon-distillation-papers.md),
[ёмкость модели и ограничения ESP32](research/dragon-tiny-model-papers.md).
