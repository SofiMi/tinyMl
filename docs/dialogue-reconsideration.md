# Решение после пересмотра моделей и данных

17 октября 2026. Пользователь выбрал **автономного дракона на ESP32 с ограниченными
разговорами и программной памятью имени и фактов**. Это новая целевая архитектура.
Свободный разговор слабой LLM больше не считается надёжным источником фактов.
Обзор первоисточников: [кандидаты](research/reconsider-dialogue-base.md).

## Что реально проверено

На оригинальных весах, с родным chat template и собственной историей модели
повторён полный разговор Sofia. Для HF: CPU FP32, контекст 256, максимум 48
новых токенов. Проверены greedy и настройки sampling из model cards, seed 42;
у Qwen дополнительно seed 43. Никакой кандидат в этом опыте не дообучался.

| Модель | Параметры | Наблюдение |
|---|---:|---|
| Stentor-30M-Instruct | 30 419 712 | Бессвязность и повторы; sampling 1.1/top-p .6/penalty 1.3 не исправил смысл |
| Doge-20M-Instruct | 13 117 712 | Выдумывает Alex/Emily, путает Sofia с драконом; sampling .8/.9 тоже не дал диалога |
| SmolLM2-360M-Instruct | 361 821 120 | Называет Sofia драконом и повторяет это даже на арифметику; .2/.9 не устранило цикл |
| Qwen3-0.6B | 596 049 920 | Greedy различил Sofia/Ember и ответил 2; на других вопросах путает владельцев и говорящего. Sampling .7/.8/top-k20 нестабилен |
| Локальный Qwen3.5:9b | Другой масштаб | На разговоре Sofia различает имена и меняет тему на арифметику; всё ещё ошибается в отдельном тесте цвета |

Qwen3 запускался с `enable_thinking=False`. Его дополнительно проверили на 12
естественных сценариях: есть связное представление и предложение игры, но
на `pear is mine, apple is yours` он меняет владельцев местами, а в паре
Niko/Elsie неверно выбирает говорящего. Это не готовый студент для сжатия.

Учитель Qwen9B проверен через уже установленный локальный Ollama/MLX, без облака,
с контекстом 2048 и temperature 0. Его результат не является сравнением скорости
или строгим benchmark с HF. Даже у него в одном разговоре потерялся факт
`I like green, not orange`; короткая история упёрлась в 48 токенов.
Ответы учителя нельзя автоматически считать правильной разметкой.

Успешный выход диагностического скрипта означает лишь отсутствие конкретного
цикла из трёх одинаковых ответов вокруг `1 + 1?`. Stentor и Doge могут получить
этот статус с бессмысленным текстом. Все выводы выше основаны на чтении ответов.
Сырой материал: [каталог результатов](evaluation/reconsider/).

Хеши weights записаны в JSON. Для первых трёх использован установленный
Transformers 5.20.1 без исполнения стороннего Python-кода. Doge потребовал
отдельных Transformers 4.48.3 / tokenizers 0.21.4 / huggingface_hub 0.28.1 /
requests 2.32.5 в `~/.cache/tinyml-doge-legacy-libs`. Основная среда не понижалась.

Новый native Doge не совместим со старыми весами. `tools/doge_legacy_eval.py`
разрешает только два просмотренных оригинальных Python-файла по фиксированным
SHA256 и ожидаемый `auto_map`, выполняет их локально. Загрузка не оставила
missing/unexpected/mismatched keys. Последние logits полного forward и
cache-forward совпали с максимальным отклонением `1.91e-5` при допуске `1e-4`.
Подробности: [loading audit](evaluation/reconsider/doge-loading.json).

```sh
python tools/diagnose_dialogue_loop.py \
  --model "$HOME/.cache/tinyml-smollm2-360m-instruct" \
  --temperature .2 --top-p .9 --output build/dragon/smol360-replay.json
PYTHONPATH="$HOME/.cache/tinyml-doge-legacy-libs" python tools/doge_legacy_eval.py loop \
  --temperature .8 --top-p .9 --output build/dragon/doge-replay.json
python tools/teacher_replay.py
```

Требуемые файлы моделей скачиваются `huggingface_hub.snapshot_download` по
указанным revision: config, generation_config, model.safetensors, tokenizer.json,
tokenizer_config, special_tokens_map, отдельный chat_template.jinja при наличии.
Для Doge дополнительно оригинальные configuration_doge.py и modeling_doge.py.
Веса не включены в Git.

## Исправление выбора данных

В прежних 1 400 общих обучающих разговорах было **ноль everyday-conversations**.
Фильтр требовал минимум два слова и удалял разные диалоги с одинаковым первым
вопросом. Для естественных разговоров с `Hello!` / `Hey!` это неверный отбор.
В результате преобладали форматирование, перефразирование и короткие задания.
Это наш дефект подготовки данных; он не доказывает, что его одного достаточно
для объяснения всех ошибок исходных и обученных моделей.

`tools/prepare_dialogue_v2.py` допускает однословное приветствие, удаляет только
дубли целых разговоров, требует минимум две полные пары и берёт источники
everyday-conversations / smol-magpie-ultra-short. Разделение train/validation
группирует первый содержательный вопрос, пропуская короткое приветствие.

Сохранён **необученный черновик**:
[training/dialogue-v2-natural-draft](../training/dialogue-v2-natural-draft/).
Train: 656 разговоров / 1 896 ответов, из них 502 повседневных разговора.
Validation: 76 / 214, из них 54 повседневных. Сценарии и все перефразировки
автоматически не разделены; это не независимый финальный benchmark.
Исправление покрыто тестами одинакового приветствия с разными темами и
разных приветствий с одной темой. Старый воспроизводимый v1 не изменён.

## Новая инженерная граница

Имя человека, имя дракона, предпочтения и принадлежность предметов принадлежат
состоянию программы. Исправления пользователя обновляют это состояние. Если факт
неизвестен или ввод неоднозначен, персонаж уточняет его вместо догадки.
Вопросы о таких фактах получают ответ из состояния. Нейросетевой текст не
записывается в память как истина.

Первая реализация уже доступна в общем C++ для host и ESP32:
[автономный дракон](autonomous-dragon.md). Проверены исходный разговор,
исправления, отдельные формы отрицания, смена темы и сброс памяти. Ограниченные игры,
приветствия и поддержка используют подготовленные короткие реплики.
Генеративную модель подключать только для тех видов ответов, где она прошла
отдельную проверку; отсутствие надёжной генерации не скрывать за названием LLM.

Это выбранный пользователем ограниченный персонаж с программной памятью.
Это не означает, что найдена универсальная LLM на 8 МБ или что Qwen можно
без доказательств сжать в десятки раз. Научно-исследовательскую ветку обучения
маленьких моделей можно продолжать отдельно от надёжного поведения игрушки.
