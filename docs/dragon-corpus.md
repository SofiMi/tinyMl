# Расширение корпуса локальным Qwen

Это подготовка **черновых обучающих данных**, а не новая обученная модель.
Прошивка и выбор модели не меняются. Обоснование масштаба и архитектуры:
[исследование](research/dragon-training-scale.md).
Замеры трёх рецептов, сырые ответы и причины отбраковки:
[пилот генерации](evaluation/qwen-corpus/README.md).

## Запуск и возобновление

Нужен уже работающий локальный Ollama-совместимый сервер с `qwen3.5:9b`.
Генератор не скачивает модели и не использует облачные API.

### Запуск на восемь часов

Из корня репозитория на Mac:

```sh
caffeinate -i python3 tools/generate_dialogues_timed.py --hours 8
```

`caffeinate` не даёт Mac автоматически уснуть, пока работает процесс.
На Linux убрать `caffeinate -i`. Не закрывать терминал. Для фонового
запуска на Mac с журналом вывода:

```sh
mkdir -p build/dragon
nohup caffeinate -i python3 -u tools/generate_dialogues_timed.py --hours 8 > build/dragon/qwen-8h.log 2>&1 &
```

Результаты — `build/dragon/qwen-8h/`, состояние — `run-status.json`.
План содержит максимум 20 тысяч попыток с отдельным seed; это запас для
таймера, а не обещание получить столько за восемь часов. Если план
закончится раньше, процесс завершится. Свободное место проверяется перед
каждым диалогом; резерв 256 МиБ. Повторный запуск продолжает готовые
диалоги и даёт **новый** восьмичасовой бюджет. Продлить или сократить
его можно через `--hours`, например `--hours 2`.

Таймер прерывает сетевое ожидание Qwen по истечении времени, затем сохраняет
экспорт и отчёт. Поэтому завершение может занять ещё время записи файлов.
Незаконченный диалог не попадает в журнал; при продолжении он повторится.
Учитель-сервер остаётся запущенным; отмена клиента не гарантирует немедленной
отмены уже выполняемого запроса внутри backend. Таймер рассчитан на
macOS/Linux и основной поток Python. Ctrl+C сохраняет законченные результаты.

Это длительный сбор **черновых кандидатов текущего рецепта**. Ошибки,
перечисленные в отчёте пилота, автоматически не исправляются. Обучение
ученика не запускается. Принятые автофильтром строки требуют проверки.

### Отдельные этапы без таймера

```sh
python3 tools/dragon_distill_data.py plan --count 2000
python3 tools/dragon_distill_data.py generate --limit 60
python3 tools/dragon_distill_data.py report
```

`--count` задаёт количество **попыток**, а не гарантированно хороших диалогов.
`--limit` ограничивает дополнительные попытки за один запуск. Повторный
запуск продолжает журнал; `--limit 0` обрабатывает весь оставшийся план.
Ctrl+C прерывает работу; законченные диалоги остаются, незаконченный запрос
будет повторён. При аварии диска посреди записи последнюю повреждённую строку
журнала потребуется восстановить вручную. Минимальный резерв диска по
умолчанию — 256 МиБ, генератор не удаляет файлы.

Результаты по умолчанию находятся в `build/dragon/qwen-dialogues-v3-3/`:

- `plan.json`: сценарии, seed и заранее назначенные группы train/validation/test;
- `manifest.json`: digest учителя, промпты и хеш генератора;
- `journal.jsonl`: все попытки, исходные ответы, причины отбраковки и время;
- `train.jsonl`, `validation.jsonl`, `test.jsonl`: прошедшие текущие фильтры записи;
- `report.json`: количество, отбраковка, приблизительная стоимость расширения.

Чтобы изменить сценарии, код генератора, модель или её digest, нужен новый
каталог `--output` и новый план. Нельзя незаметно смешивать разные рецепты.
Версия рецепта также должна меняться при изменении содержания сценариев.
Одновременные процессы в одном каталоге запрещены файловой блокировкой.

## Что именно генерируется

Четыре обмена репликами, 12 групп задач: приветствие, выбор, поддержка,
планирование, история, объяснение, идентичность, исправление имени, друг,
предпочтение, принадлежность предметов и неизвестный факт.

В шести задачах с фактами программа задаёт пользовательские вопросы, чтобы
учитель не менял «моё имя» на «твоё имя». **Все ответы пишет Qwen**; это не
шаблонный бот и не изменение поведения прошивки. Каждый следующий ответ
видит реальные предыдущие ответы учителя. В остальных задачах учитель
сочиняет обе стороны беседы.

Проверяются структура, ограничения длины, некоторые перепутанные роли,
ожидаемые факты и точные дубликаты. Затем тот же Qwen оценивает беседу.
Локальный MLX backend возвращает 501 на constrained structured output,
поэтому JSON запрашивается промптом и строго разбирается после генерации.
Невалидный или обрезанный результат отбрасывается.

**Самооценка Qwen ненадёжна:** в пилотах она пропускала неправильные ответы
и отвергала правильные по выдуманным причинам. Экспортированные строки —
кандидаты для проверки, не сертифицированный корпус. Для исключения записи
создать `manual-review.json`, затем выполнить `report`:

```json
{
  "id-из-журнала": {
    "pass": false,
    "reason": "Противоречие предыдущей реплике",
    "reviewer": "кто проверил"
  }
}
```

Ручное `pass: true` не возвращает автоматически отбракованную запись.
Сначала сохранить отдельный независимый набор настоящих вопросов пользователя.
Синтетические test-сценарии не заменяют такой тест. Группы разделены по
семейству/теме/месту, имена — по split; общие шаблоны и семантически близкие
разговоры всё равно могут пересекаться.

Текущий набор из 16 тем, 8 мест и небольшого пула имён предназначен для
пилота. Для 50–150 тысяч диалогов нужно расширить сценарии, разговорные
формулировки, неизвестные факты, опечатки и длины бесед, а также проверять
смысловые дубликаты. Простое увеличение `--count` этого не делает.

## Считать токены, а не только диалоги

В окружении с установленным `sentencepiece`:

```sh
python tools/dragon_corpus_budget.py \
  --data build/dragon/qwen-dialogues-v3-3 \
  --tokenizer /path/to/tokenizer.model \
  --output build/dragon/qwen-dialogues-v3-3/token-budget.json
```

Это оценка с протоколом stories15M (`User/Dragon`, EOS), без системного
промпта. Она не означает выбор этой модели. Отдельно считаются токены
ответов для loss, длина полной истории и переполнение контекстов 256/512.
Токенизатор обрезанного TinyTalk на ESP отличается. Проверка на 64 токена
иллюстрирует бюджет 72 минус 8, а не воспроизводит весь runtime.

Экспорт содержит системное сообщение и четыре пары user/assistant.
Старому `dragon_student.py`, который ожидает только чередующиеся пары,
нужна явная адаптация формата; нельзя просто передать ему эти файлы.
Обучение и загрузка весов здесь автоматически не запускаются.

## Как принимать решение об увеличении

Сначала качественная проверка сотен примеров и около 2000 попыток. Затем
контролируемое сравнение на 10 тысячах принятых диалогов. Следующая гипотеза:
50–150 тысяч разнообразных диалогов для SFT уже языковой основы. Для новой
архитектуры потребуется отдельное предобучение; этот размер SFT не обещает
научить язык с нуля. Время в отчёте — экстраполяция генерации с отбраковкой,
без времени человека на проверку, обучения ученика и его тестирования.

Проверка инфраструктуры:

```sh
python3 -m unittest discover -s tools -p test_dragon_distill_data.py
python3 -m unittest discover -s tools -p test_generate_dialogues_timed.py
```

Локальная проверка 17 октября 2026: 12 тестов прошли. Реальный прогон с
Qwen на 36 секунд сохранил четыре завершённых диалога; повторный запуск
на 12.6 секунды продолжил с пятого и остановился за 12.608 секунды.
Незаконченный шестой диалог в журнал не попал. Полный восьмичасовой
прогон при этой проверке не запускался.
