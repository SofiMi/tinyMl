# Проверка качества TinyTalk 2 на компьютере

Дата: 2026-10-17. CPU macOS arm64, temperature=0, максимум 48 новых токенов.
PyTorch 2.14.1, Transformers 5.20.1. Сырые результаты: [tinytalk-quality.json](tinytalk-quality.json).

Проверены 17 фиксированных запросов: знакомство, имя пользователя, реплики
из пользовательского лога, три задания на роль дракона и восемь элементарных
вопросов из upstream-проверки. Это диагностические примеры, не независимый
бенчмарк и не оценка общего качества или русского языка.

## Контроль происхождения

Движок, веса и токенизатор совпали побайтно с cardputer-ai
`78c5128672b750977619dc0a6c3b8baed91168ed`. Из токенизатора восстановлен список
сохранённых ID исходного словаря. Повторная конвертация локального checkpoint
`data/chat_model_8m/model.safetensors` с этим списком и 256 позициями дала
байт-в-байт исходный `model_neo_q4.bin` (SHA-256
`183fe4c212fd0fd17a8e048ee3eab4a0095a039df290f0c58cafff70ca17fe2a`).

## Метод

FP32 запускался через Hugging Face Transformers с eager attention.
Квантованный вариант — через upstream host harness, скомпилированный с
движком из нашего проекта. Для основного сравнения входные ID токенов
одинаковы; в FP32 они отображены обратно в исходный словарь. Выходной
словарь FP32 полный, поэтому это сравнение всего сжатого варианта с FP32,
а не изолированная оценка только 4-битных весов.

Для 14 из 17 запросов токенизация совпала с полным GPT-2-словарём. В трёх
запросах про дракона она отличалась после сокращения словаря; восстановленный
текст совпал для всех 17. Для этих трёх запросов отдельно сохранён ответ FP32
при собственной токенизации (`fp32_native_tokenization`).

## Результаты

- В контролируемой истории из 31 токена явно присутствует имя Sofia и
  правильное приветствие. На вопрос об имени собеседника FP32 отвечает
  `My name is Sarah.`, а сжатая версия — `I'm Sarah.`. Это не выпадение
  исходного имени из 72-токенного контекста.
- В истории из 34 токенов дракон прямо назван Ember. На следующий вопрос
  о его имени обе версии отвечают `My name is Lily.`.
- На восьми элементарных вопросах FP32 содержит ожидаемое ключевое слово
  в 8/8 ответах, сжатая версия — в 7/8. Например, `puppy` заменяется на
  `dog`. Это небольшая проверка знакомых модели фактов, не общая accuracy.
- KV=72 и KV=256 дали одинаковый текст на всех 17 коротких запросах.
  Это не проверяет преимущества большего контекста на длинных разговорах.
- Наша консоль и upstream harness дали одинаковые ответы на всех четырёх
  ходах диалога `hello → my name is sofia → what language do you speak? →
  what is my name?`, включая восстановление и обрезку истории.
- Отдельный прогон этого диалога, `/new` и `Hi!` под AddressSanitizer и
  UndefinedBehaviorSanitizer завершился без диагностик. Leak detection был
  отключён: upstream оставляет модель и рабочий поток на всё время процесса.

Слабое удержание имени и роли воспроизводится у исходной FP32-модели.
Сжатый вариант дополнительно меняет некоторые ответы. Ошибки переноса
консоли в этих сценариях не выявлены; отсутствие любых ошибок движка этим
не доказано. Xtensa SIMD и текущая прошивка на плате не сравнивались с CPU
побитно; аппаратный seed при temperature=0.8 неизвестен, поэтому ответы
пользовательского лога не обязаны совпасть с этими greedy-прогонами.

## Повторение

В отдельном Python-окружении установите `torch==2.14.1`,
`transformers==5.20.1`, `safetensors==0.8.0`, `numpy==2.2.6`.
Нужен C++17-компилятор и локальная копия cardputer-ai указанного выше commit,
включая `data/chat_model_8m/model.safetensors`:

```sh
python tools/evaluate_quality.py --upstream /path/to/cardputer-ai
```

Скрипт не скачивает модели и не изменяет прошивку. Сборка, повторно
сконвертированные веса и новые результаты сохраняются в `build/evaluation/`.
