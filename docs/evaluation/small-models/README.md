# Локальная проверка трёх кандидатов — 2026-10-18

Все три модели скачаны и запущены на Mac. Два GGUF используют Q4_K_M;
VaghLM — доступный `best_checkpoint.pt` в FP32, не отсутствующий
`finetuned_v2_best.pt`. Обучение и перенос на ESP не выполнялись.

Запуск: [меню и команды](../../small-models-playground.md).
Источники, версии и SHA-256 — [receipt.json](receipt.json), настройки и точные
входные/выходные ID — в JSONL рядом. [report.json](report.json) содержит
результаты проверки транспорта и примеры ответов.

Проверены реальные CLI и инференс всех трёх моделей: независимость запросов,
`/new`, `/stats`, `/quit`; для Stentor/VaghLM дополнительно история с собственным
предыдущим ответом, сброс и отказ от слишком длинного ввода без его обрезания.
Перед запуском Q4 проверяется весь словарь ID → текст HF против GGUF.

Это **не положительная оценка качества**. На двух пробных запросах:

- Stories продолжает английские истории, но подменяет имя Ramil на Rex и
  затем Ross; связность персонажей ненадёжна.
- Stentor выдаёт несвязанные рассуждения и библиографический текст вместо
  знакомства или ответа о цвете травы.
- VaghLM путает имя собеседника, а на вопрос о цвете травы пишет про углекислый
  газ и экосистемы, не отвечая на вопрос.

Количество проб мало; вывод о превосходстве одной разговорной модели над другой
делать нельзя. Пользователю предоставлен запуск для собственной проверки.

При интеграции обнаружено несовпадение разбиения инструкционных маркеров Stentor
в опубликованном GGUF и исходном HF-токенизаторе. Конечный код использует исходный
HF-токенизатор и прямую передачу ID в llama.cpp, включая BOS/EOS, и декодирует
ответ тем же токенизатором. Оригинальные Q4-файлы не изменены.

Проверки прошли вне песочницы с llama-cpp-python 0.3.16 и `n_gpu_layers=0`.
На Mac пакет принудительно включает Metal при сборке, даже при
`GGML_METAL=OFF`; наличие библиотеки Metal не означает перенос слоёв модели
на GPU. Скорость этого запуска не переносится на ESP32.
